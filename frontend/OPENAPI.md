# Frontend API types (OpenAPI)

The backend exposes an OpenAPI schema (FastAPI) that is committed at the repo
root as `openapi.json`. It is regenerated by `scripts/export_openapi.py`:

```bash
python scripts/export_openapi.py
```

CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml), "OpenAPI drift
check") re-runs the exporter into a temp file and fails if the committed
`openapi.json` differs, so the artifact cannot silently drift from the backend.

## Generating TypeScript types (intentional next step, not wired yet)

The frontend still uses hand-written response interfaces inside components
(e.g. `src/app/components/AdminSecurity.tsx`, `AdminUsersTab.tsx`). Those are
not yet replaced. When the artifacts are wired in, generate the types with:

```bash
cd frontend
npx openapi-typescript ../openapi.json -o src/lib/api-types.ts
```

This is deliberately NOT added as an npm dependency or as a build/lint step
yet: wiring the generated types into the components is a separate change so it
can be reviewed on its own.

## Rules for keeping types in sync

1. Any change to backend request/response schemas must be followed by
   re-running `python scripts/export_openapi.py` (and committing the updated
   `openapi.json`) in the same change.
2. Do not hand-edit `openapi.json`: it is derived, and CI will reject drift.
3. Until the `openapi-typescript` step is wired, treat `openapi.json` as the
   single source of truth for the backend contract.
