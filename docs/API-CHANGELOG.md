# API CHANGELOG

Изменения HTTP API. Базовый префикс - `/api` (совместимый алиас `/api/v1`,
в схеме не публикуется). Заголовок версии не вводился - ломающие изменения
помечены ниже явно.

---

## Пагинация `GET /api/forecast/all`

Раньше эндпоинт отдавал все прогнозы сразу (~780 навыков, ~3 МБ одним
ответом). Теперь применяются `limit`/`offset`, а в ответе возвращается общее
число.

**Параметры:** `months` (1..24, по умолчанию 12), `limit` (1..5000, по умолчанию
500), `offset` (>= 0, по умолчанию 0), `min_freq` (>= 0) - отсечь
низкочастотный хвост по `current_frequency`.

**Ответ:**

```json
{
  "total": 780,
  "limit": 500,
  "offset": 0,
  "months": 12,
  "forecasts": [ ... ],
  "...": "поля движка (_engine_info)"
}
```

**Ломающее:** раньше был голый список прогнозов; теперь объект-обёртка.
Клиенту, которому нужен весь список, следует идти страницами
(`offset += limit`, пока `offset < total`).

## Пагинация `GET /api/admin/monitoring`

Раньше отдавал все семейства метрик (сотни строк, растёт с каждым новым
эндпоинтом). Теперь - фильтр по именам и пагинация.

**Параметры:** `names` (список имён метрик через запятую), `limit` (1..1000,
по умолчанию 100), `offset` (>= 0, по умолчанию 0).

**Ответ:**

```json
{
  "total": 435,
  "limit": 100,
  "offset": 0,
  "families": {
    "http_requests_total": { "name": "...", "type": "counter", "samples": [ ... ] }
  }
}
```

**Ломающее:** ключ `families` теперь содержит только запрошенную страницу, а
не всё; полное число семейств - в `total`.

## 2FA: мастер-переключатель и подключение

2FA управляется **одним флагом на всю систему**, по умолчанию выключенным.
Флаг хранится в таблице `app_settings` (ключ `security.two_factor`), а не в
`.env` и не в JSON-файле: переключение действует сразу на все процессы и
переживает деплой.

| Метод | Роут | Назначение |
|-------|------|------------|
| GET | `/api/auth/2fa/policy` | **без авторизации**: `{"enabled": bool}` для экрана входа |
| GET | `/api/auth/2fa/status` | состояние текущего пользователя |
| GET | `/api/admin/security/2fa/settings` | `{"enabled": bool, "enrolled_admins": int}` |
| PUT | `/api/admin/security/2fa/settings` | включить/выключить: `{"enabled": true}` |
| POST | `/api/auth/2fa/setup` | создать секрет, вернуть `otpauth_uri`, `secret`, `enroll_id` |
| POST | `/api/auth/2fa/confirm` | подтвердить код, вернуть `recovery_codes` (одноразовые) |
| POST | `/api/auth/2fa/verify` | завершить вход по `challenge_id` + TOTP-код |
| POST | `/api/auth/2fa/recovery` | вход по одноразовому recovery-коду |
| POST | `/api/auth/2fa/disable` | отключить 2FA (нужен TOTP- или recovery-код) |

`GET /api/auth/2fa/status` отдаёт поля в двух именованиях одновременно:
`globally_enabled`/`configured`/`confirmed` (исходные) и
`enabled`/`enrolled`/`available` (то, что читает админка).

**Выключение не удаляет подключения.** При повторном включении те же
пользователи снова получают запрос кода.

**Изменение поведения входа.** Когда переключатель включён:

| Кто | Ответ `POST /api/auth/login` |
|---|---|
| подключил TOTP | `{"status": "totp_required", "challenge_id": ..., "expires_in": 300}` |
| админ без TOTP | `{"status": "totp_setup_required", "enroll_id": ..., "expires_in": 600}` |
| не админ без TOTP | обычный токен (иначе включение заперло бы всех сразу) |

`enroll_id` - одноразовый пропуск на настройку без сессии: `setup` и `confirm`
принимают его в теле запроса. Успешный `confirm` по пропуску сразу возвращает
`token` вместе с `recovery_codes`.

**Пока переключатель выключен**, все `/api/auth/2fa/*` отвечают `403` с
`{"detail": "Двухфакторная аутентификация отключена администратором"}`, а вход
одношаговый для всех - включая тех, кто уже подключил TOTP.

**Ломающее:** клиенты, которые всегда ждали `token` от `/auth/login`, должны
обработать `status`-ответы выше (это уже делают `LoginPage` и `smoke-get.py`).
Подробности - в `docs/RUNBOOK.md`, раздел «2FA администратора».

## Скрытие `output`/`logs` в задачах пайплайна

`GET /api/pipeline/task/{task_id}` и `GET /api/pipeline/active` отдают полные
детали (`output`, `logs`) только владельцу задачи и админу. Остальным
авторизованным (`teacher`, `rop`) возвращаются метаданные и прогресс, а поля
`output` и `logs` обнуляются (`output: null`, `logs: []`).

Причина - приватность чужого сбора: в `output`/`logs` попадают работодатели,
регионы и поисковые запросы. `GET /api/pipeline/tasks` применяет то же правило
к списку.

**Совместимость:** формат ответа не менялся, `output`/`logs` могут быть пустыми
у не-владельца - клиент не должен на них полагаться как на индикатор ошибки.

## `429 Too Many Requests` с `Retry-After`

Rate-limit (slowapi) и блокировка после серии неверных 2FA-кодов теперь
возвращают `429` и заголовок `Retry-After` (в секундах) - сколько ждать до
следующей попытки. Клиенту следует уважать этот заголовок и не ретраить
немедленно.

---

## WebSocket без `?token=`

`WS /api/pipeline/ws` (и `/admin/logs/ws`) больше **не принимают токен в
query-строке**. Аутентификация - только через cookie (`token`) или заголовок
`Authorization: Bearer <token>`. При отсутствии/недействительности сессии
соединение закрывается с кодом `4001`.

**Ломающее для клиентов**, которые подключались как `.../ws?token=...` -
переведите авторизацию на cookie или заголовок.
