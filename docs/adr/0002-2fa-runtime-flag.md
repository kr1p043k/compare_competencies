# ADR 0002: 2FA как runtime-флаг, чтение fail-closed

- Статус: Принято
- Дата: 2026-11-09

## Контекст

Второй фактор (TOTP) для админов изначально был всегда включён, а настройка
хранилась в отдельном файле-флаге, который сам вход не читал: тумблер
переключался, но защита не менялась. Отдельно выяснилось, что чтение
мастер-флага из БД при сбое возвращало `enabled=False`, то есть ошибка чтения
тихо снимала второй фактор.

## Решение

- Единственный источник правды по 2FA - таблица `app_settings`, ключ
  `security.two_factor` (`src/api_pkg/security_settings.py`). Файловый
  флаг-дубль удалён.
- Мастер-флаг выключен по умолчанию. Вход и SSO спрашивают второй фактор
  только когда флаг включён; включается на лету через
  `PUT /admin/security/2fa/settings`.
- Чтение мастер-флага **fail-closed**: при ошибке чтения (сбой БД, битое
  значение) считаем 2FA ВКЛЮЧЁННОЙ. Штатное «нет строки» и отсутствие пула -
  это не ошибка чтения, тогда выключено по умолчанию.

## Последствия

- Плюс: сбой БД не открывает вход без второго фактора; оператор управляет
  защитой без перезапуска.
- Минус: при недоступности БД вход всё равно не проходит (нужен пароль +
  возможный второй фактор), но это осознанный приоритет безопасности.
