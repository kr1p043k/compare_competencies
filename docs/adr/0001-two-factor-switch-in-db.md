# ADR-0001: Master-switch 2FA хранится в БД, а не в файле-флаге

## Статус

accepted (заменил прежний файловый флаг; см. коммит `551b7aad`).

## Контекст

Раньше включение второго фактора (2FA) жило в файле-флаге
(`src/api_pkg/feature_flags.py`, `data/settings/features.json`), который
переключался через `/admin/features`. Проблема: login гейтил 2FA по ДРУГОМУ
источнику (`app_settings`), поэтому тумблер переключался, а второй фактор
фактически не включался - два источника истины расходились. Файл ещё и
не переживал горизонтальное масштабирование (несколько инстансов).

## Решение

Единственный источник истины - таблица `app_settings` в БД, читается через
`src/api_pkg/security_settings.py::get_two_factor_enabled(pool)`. Управление -
`GET/PUT /admin/security/2fa/settings`. Файловый модуль
`src/api_pkg/feature_flags.py` и эндпоинты `/admin/features` удалены.

## Последствия

- Плюс: login и тумблер читают один источник; состояние общее для всех инстансов.
- Плюс: переключение без рестарта, есть аудит-запись.
- Минус: чтение флага требует БД; при ошибке БД поведение задаётся явно
  (fail-closed), а не «тихо выключено».
- Минус: `/admin/features` больше нет - клиенты, которые его звали, получают 404.
