# ADR-0007: Единый конверт ошибок API

## Статус

accepted.

## Контекст

Ответы об ошибке отдавались непоследовательно: FastAPI по умолчанию отдавал
`{"detail": ...}`, у необработанных исключений добавлялся `request_id`, ошибки
валидации приходили списком без общего идентификатора, а ответы middleware
(413, 400, 429) не содержали `request_id` вовсе. Клиенту было трудно
обрабатывать ошибки единообразно, а сопоставить ответ с записью в логах - без
общего идентификатора - почти невозможно.

## Решение

Все ответы об ошибке несут общий конверт:

```json
{ "code": "not_found", "message": "Not Found", "request_id": "<uuid>", "detail": "Not Found" }
```

- `code` - машинный слаг по HTTP-статусу (`not_found`, `unauthorized`,
  `validation_error`, `rate_limited`, `payload_too_large`, `internal_error`, ...);
- `message` - строка для показа;
- `request_id` - идентификатор запроса (он же в заголовке `X-Request-ID`);
- `detail` - сохранён без изменений для обратной совместимости клиентов;
- ошибки валидации дополнительно несут список `errors`.

Реализация: хелпер `_error_body` в `src/api_pkg/__init__.py`, четыре
`exception_handler`. Обработчик `HTTPException` переведён на базовый
`StarletteHTTPException`, чтобы ловить и 404 маршрутизатора.

## Последствия

- Плюсы: единый разбор ошибок на клиенте и в логах; `code` для машинной логики,
  `request_id` для корреляции ответа с логами и метриками.
- Минусы: `detail` дублирует `message` - временно, ради совместимости; поля
  конверта нужно поддерживать при добавлении новых обработчиков.
- Проверка: `tests/api/test_error_envelope.py` (404/401/422).
