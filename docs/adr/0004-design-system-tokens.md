# ADR-0004: UI строится на токенах и примитивах дизайн-системы

## Статус

accepted.

## Контекст

По фронтенду были разбросаны инлайн-стили (`style={{}}`) и хардкод-цвета
(`bg-gray-100`, `text-slate-400`, `text-emerald-600` и т.п.). Это ломало
dark-mode (серые/цветные классы не имеют токен-версии), мешало единообразию
и усложняло ревью.

## Решение

Все экраны используют токены Tailwind, привязанные к CSS-переменным темы
(`text-foreground`, `text-muted-foreground`, `text-subtle-foreground`,
`text-primary/success/warning/destructive`, `border-border`, `bg-card` ...),
и примитивы из `src/design` (`PageHeader`, `EmptyState`, `ErrorState`, `Card`,
`CardBody`, `Badge`, `Button`, `Table`, `inputClass`, `Skeleton`, `Meter` ...).
Инлайн `style={{}}` и хардкод-цвета в компонентах запрещены.

## Последствия

- Плюс: light/dark работают из коробки; единый вид; меньше дублей.
- Плюс: смена темы/палитры - в одном месте (токены).
- Правило проверки: миграция UI принимается только с >=2 независимыми
  ревьюерами и скриншотами light/dark.
- Минус: новые компоненты обязаны идти через `src/design`, нельзя «быстро
  накидать» цветных классов.
