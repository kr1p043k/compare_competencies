# ADR-0004: Версионирование публичного API

## Статус

accepted.

## Контекст

Claude/PM и внешние потребители (frontend, n8n, интеграторы) обращаются к
HTTP-контракту. Нужен явный признак «какая версия контракта на сервере» и
правило, как вводить несовместимые изменения, не ломая клиентов молча.
Плюс `openapi.json` должен оставаться синхронным (CI drift-гейт).

## Решение

- Все маршруты сейчас живут под `/api`.
- `GET /api/version` возвращает `{"api_version": "<X.Y>"}` (значение из
  `config.API_VERSION`).
- При несовместимом изменении поднимаем major и уводим старые пути под
  `/api/v1` (обратная совместимость на переходный период).
- Изменения контракта фиксируются в `docs/API-CHANGELOG.md`.
- Закоммиченный `openapi.json` обязан совпадать с кодом; дрейф ловит CI-шаг
  `OpenAPI drift check` (экспортёр - `scripts/export_openapi.py`).

## Последствия

- Плюс: клиент может проверить версию; есть процедура для breaking changes.
- Плюс: контракт не «плывёт» незаметно - drift-гейт в CI.
- Минус: любое изменение эндпоинтов требует регенерации `openapi.json` в том же
  коммите (той же версией FastAPI, что ставит CI).
